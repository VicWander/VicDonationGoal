# Tribute — подключение по ссылке для OBS

Tribute получает донаты напрямую по персональной OBS-ссылке. Cloudflare, публичный сервер, API-ключ и скрытый браузер для этого не нужны. Сам OBS может быть закрыт.

## 1. Скопируйте ссылку

- Откройте мини-приложение Tribute в Telegram.
- Перейдите в «Донаты и цели» и откройте интеграцию с OBS.
- Нажмите «Копировать ссылку для OBS».
- Нужна ссылка вида `https://obs.tribute.tg/obs/alerts?...`, а не страница для оплаты доната.

## 2. Подключите в VicDonationGoal

- Вставьте ссылку целиком в поле «Ссылка для OBS из Tribute».
- Нажмите «Сохранить», включите интеграцию и запустите её.
- Если меняете ссылку или настройку прокси при работающем модуле, сохраните настройки и нажмите «Перезапустить».
- Дождитесь статуса «Подключено». Он означает, что поток действительно присылает данные, а не только запущен процесс.

Ссылка содержит личный токен: не публикуйте её для зрителей. В интерфейсе и диагностике она скрывается.

## 3. Проверьте донат

- По умолчанию «Учитывать донаты во время проверки» выключено.
- В VicDonationGoal нажмите «Проверить донат из Tribute».
- Дождитесь подключения потока. В течение двух минут нажмите «Отправить тестовый донат» в мини-приложении Tribute.
- В карточке появятся имя, сумма и время последней проверки. Событие не добавится в историю и цель, если переключатель выключен.
- Нажмите «Завершить проверку», чтобы сразу вернуть обычный учёт. Иначе режим завершится автоматически через две минуты.

Tribute не передаёт признак теста. Поэтому режим проверки применяется ко всем событиям, полученным в это время, включая настоящие платежи. Проверяйте подключение до стрима. Если хотите учитывать события и в этом режиме, включите переключатель и сохраните настройки — перезапуск для этого переключателя не требуется.

Вне режима проверки учитываются все донаты: имя Anonymous и сумма 999 ₽ не являются признаком теста. Тест из мини-приложения, отправленный вне режима проверки, тоже попадёт в историю и цель.

## Соединение и доставка

- После разрыва приёмник переподключается автоматически.
- ID платежа используется для защиты от повторного учёта.
- Если событие уже получено, но Core недоступен, оно сохраняется в локальной очереди и отправляется повторно, в том числе после перезапуска.
- Получение платежей, совершённых пока вся программа была выключена, пока не подтверждено. Нельзя считать поток полной историей платежей.
- По умолчанию используется системный прокси. Если соединение не устанавливается, можно выключить эту настройку, сохранить и перезапустить интеграцию. Полный VPN-туннель этой галочкой не обходится.

Интеграция пока Experimental: тестовый поток проверен, проверка настоящего платежа и одновременной доставки в OBS остаётся отдельным этапом.

## Если раньше использовали webhook

Для подключения по OBS-ссылке старые API-ключ и URL webhook не нужны. Старые настройки сохранены локально для восстановления, но новая карточка их не использует. При заполненной OBS-ссылке Core отклоняет прежний webhook, чтобы не учитывать одно событие двумя способами. Старый адрес в настройках API Tribute можно очистить: он больше не нужен.
