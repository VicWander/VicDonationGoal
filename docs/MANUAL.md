# Техническая справка VicDonationGoal 1.5

Справочник описывает поведение и параметры публичной версии 1.5. Практические уроки по редактору, ИИ и оповещениям находятся в Гайдбуке админки. История изменений — в CHANGELOG_v1.5.md.

## Установка, запуск и обновление {#installation}

### Требования

Windows 10/11, Python 3.11+ с pip. OBS Studio нужен для отображения виджета и воспроизведения браузерного TTS. Streamer.bot и Speaker.bot устанавливаются и запускаются отдельно, если используются. Для загрузки зависимостей, авторизации и приёма событий нужен интернет. Серверная часть работает локально; обязательного облачного аккаунта VicDonationGoal нет.

| Назначение | Команда или адрес | Поведение |
|---|---|---|
| Установка | `00_INSTALL_ALL.bat` | Устанавливает Python-зависимости, браузер Playwright и создаёт недостающие настройки |
| Обычный запуск | `01_START_ALL.bat` | Останавливает старые процессы этой установки, запускает Core, включённые интеграции и TTS Hub |
| Только Core | `02_START_SERVER_ONLY.bat` | Менеджер интеграций работает внутри Core |
| Админка | `http://127.0.0.1:3333/admin.html` | Локальное управление программой |
| Донат-гол | `http://127.0.0.1:3333/widget.html` | Источник «Браузер» в OBS |
| Аудио TTS | `http://127.0.0.1:3333/tts.html` | Браузерный проигрыватель для провайдеров, создающих аудиофайл |
| Остановка | `13_STOP_ALL.bat` | Завершает процессы данной установки |
| Предпросмотр админки | `17_PREVIEW_ADMIN.bat` | Отдельный режим на порту 3347; внешние подключения, оповещения и звук отключены |

Предпросмотр не является песочницей данных: изменения форм, импорт и редактор затрагивают данные той папки, из которой он запущен. Для экспериментов нужна отдельная копия. Зелёный Core означает связь админки с локальным сервером, а не доставку событий всех сервисов.

### Обновление

Новая версия распаковывается отдельно. После остановки обеих установок `16_UPDATE_FROM_OLD_VERSION.bat` запускается из новой папки и получает путь к старой. Исходная папка сохраняется. Переносятся поддерживаемые данные и подключения, но не старый программный код. Версия целевой программы сохраняется.

Импортированные старые донаты помечаются обработанными для TTS и Streamer.bot; незавершённая очередь озвучки не запускается заново. Повторный перенос не предназначен для смешивания двух одновременно работающих историй. Не запускайте две версии с одними внешними подключениями одновременно.

## Донаты, цель и TopDonation {#donations}

### Расчёт текущей цели

В 1.5 одна текущая цель. Её сумма складывается из `baseAmount` и записей с включённым `includeInGoal`. Суммы других валют приводятся к валюте цели; в записи сохраняется `amountForGoal`. Изменение текущего курса само по себе не заменяет сохранённые суммы прошлых переводов.

| Параметр | Значение |
|---|---|
| Название | Текст цели для админки и виджета |
| Стартовая сумма / `baseAmount` | Деньги без отдельной записи о донате; не создаёт донатера и сообщение |
| Цель / `goal` | Сумма, с которой сравнивается прогресс |
| Собрано / `current` | Стартовая сумма плюс учитываемые записи |
| Процент | Отношение собранного к цели; может быть больше 100% |
| Осталось | Неотрицательная разница между целью и собранным |

Индикатор заполнения ограничивается 100%, текст процента может показывать превышение. Сброс текущего сбора сохраняет историю и TopDonation, но убирает старые записи из текущей цели.

### Флаги отдельного доната

| Поле | Назначение | Что не меняет |
|---|---|---|
| `includeInGoal` — в сборе | Включает сумму в текущую цель | Не удаляет историю и не управляет TopDonation |
| `includeInTop` — в TopDonation | Включает запись в рейтинг | Не меняет сумму текущей цели |
| `notifyStreamerBot` — оповещение | Разрешает основной Action Streamer.bot | Не включает TTS и дополнительные ивенты |
| `triggerDonationEvents` — ивенты | Разрешает дополнительные правила Streamer.bot | Не заменяет обычное оповещение |
| `speakTTS` — озвучка | Разрешает обработку сообщения TTS Hub | Не гарантирует речь: остаются фильтры, профиль и доступность провайдера |

У автоматических донатов значения по умолчанию определяются обработчиком события. Ручная форма позволяет выставить их независимо. Основное оповещение Streamer.bot и TTS Hub — отдельные пути: добавление озвучки ещё и в Action может дать двойное чтение.

### История и идентификаторы

`source` указывает источник, `externalId` — идентификатор события в сервисе, `uniqueKey` используется для защиты от дублей. `createdAt` — время события, `receivedAt` — время получения программой. Одинаковое имя не является достаточным признаком одного платежа или одного человека.

Редактирование флагов пересчитывает соответствующие представления. Удаление записи убирает её из истории и влияет на расчёты. CSV-экспорт — таблица для просмотра; полный бэкап предназначен для восстановления программы.

### TopDonation

Профиль донатера связывается с алиасами и источниками. Одинаковые ники из разных сервисов изначально могут быть разными профилями. Объединение связывает записи с общим `donorId`; сумма не должна добавляться второй раз. Заметка, отображаемое имя и закрепление — свойства профиля.

| Действие | Последствие |
|---|---|
| Закрепить | Показывает профиль отдельно над основным рейтингом |
| Корректировка суммы | Меняет только TopDonation, может быть отрицательной; не создаёт обычное событие доната |
| Исключить из топа | Сохраняет историю и сбор, скрывает участие в рейтинге |
| Объединить профили | Собирает алиасы и связанные донаты в одном профиле |
| Удалить все донаты профиля | Удаляет связанные записи и корректировки, затем пересчитывает данные; требует подтверждения |

Импорт таблицы DonationAlerts создаёт снимок для TopDonation. Уже известные отдельные события вычитаются из суммарных значений, чтобы не задвоить рейтинг. Повторный импорт обновляет снимок. Такой импорт не воспроизводит старые оповещения и не равен получению отдельных live-событий.

## Виджет и редактор {#widget}

### Состояния оформления

| Состояние | Назначение |
|---|---|
| Черновик / `draft` | Рабочий документ; сохраняется автоматически |
| Активное оформление / `active` | Документ, показываемый в OBS после применения |
| Предыдущее / `previousActive` | Предыдущее применённое оформление для восстановления |
| Сохранённые варианты / `saved` | Библиотека пользовательских документов |

Редактирование черновика не меняет OBS до применения. Готовые оформления копируются в обычные слои и доступны для изменения. Экспорт оформления в ZIP включает используемые локальные ресурсы; полный бэкап дополнительно включает личные данные всей программы.

### Типы и геометрия слоёв

Типы: `text`, `progress`, `shape`, `image`, `group`, `custom`. Слои имеют стабильные ID; `parentId` связывает слой с группой. Порядок слоёв определяет перекрытие. Видимость и блокировка редактирования — независимые свойства.

| Поле | Единицы / пределы | Значение |
|---|---|---|
| Холст `width`, `height` | Целые 16–8192 px | Логические размеры документа, отдельно от масштаба предпросмотра |
| Слой `x`, `y` | −16384…16384 px | Координаты слоя |
| Слой `width`, `height` | 1–8192 px | Размер слоя |
| `rotation` | −360…360° | Поворот |
| `opacity` | 0…1 | Непрозрачность |
| `visible` | true / false | Постоянная видимость |
| `locked` | true / false | Защита от случайного изменения в редакторе |

Документ содержит до 100 слоёв, вложенность групп — до 8 уровней. Циклические связи и повторяющиеся ID не принимаются. Масштаб «Вписать» подбирает показ холста, 1:1 соответствует логическим пикселям; это не изменение размеров самого документа.

### Текст и подстановка данных

Токены записываются в двойных фигурных скобках: `{{title}}`, `{{current}}`, `{{goal}}`, `{{remaining}}`, `{{percent}}`, `{{currency}}`, `{{lastName}}`, `{{lastAmount}}`, `{{lastMessage}}`. Они подставляют данные цели и последнего доната. Обычный текст вокруг токенов остаётся без изменений.

| Настройка | Допустимые значения |
|---|---|
| Длина текста слоя | До 4000 символов |
| Шрифт `fontSize` | 1–2048 px |
| Насыщенность `fontWeight` | 100–1000 |
| Межстрочный интервал `lineHeight` | Множитель 0,1–10 |
| Межбуквенный интервал `letterSpacing` | −100…100 px |
| Выравнивание | left / center / right |
| Регистр | none / uppercase / lowercase / capitalize |
| Длинный текст `textFit` | wrap — перенос; shrink — уменьшение; ellipsis — сокращение; scroll — прокрутка |
| Десятичные знаки `format.decimals` | Целое 0–4 |
| Валюта `format.currency` | code / symbol / none |
| Округление `format.rounding` | round / floor |
| Компактная запись `format.compact` | true / false |

Минимальный размер шрифта ограничивает уменьшение в режиме shrink. Для переносов учитывается ширина и высота слоя. Форматирование сумм относится к их отображению, а не к исходной сумме платежа.

### Цвет, форма, тень

Палитра документа содержит `primary`, `secondary`, `text`, `surface`, `track`. Значения `@primary` и другие ссылки используют соответствующий цвет палитры: изменение палитры обновляет связанные элементы. Можно задать буквальный цвет вместо ссылки. Поддерживаются HEX, названия цветов и числовые rgb/rgba/hsl/hsla; произвольные CSS-выражения в обычном поле цвета не принимаются.

`fill` — заполнение, `fill2` — второй цвет градиента, `gradientAngle` — угол. `stroke` и `strokeWidth` задают контур. `radius` — скругление. Тень задаётся цветом, размытием и смещениями X/Y. У текста есть отдельные цвет и толщина обводки. Тема админки не меняет палитру OBS-виджета.

### Прогресс и маски

| Поле | Значения / смысл |
|---|---|
| `shape` | bar, ring, arc, segments, mask |
| `direction` | right, left, up, down, center |
| `track` | Цвет незаполненной части |
| `segments` | Целое 1–1000, число сегментов |
| `gap` | Промежуток, 0–8192 px |
| `startAngle`, `sweep` | Начальный угол −360…360°, развёртка 0…360° |
| `thickness` | Толщина, 0–8192 px |
| `maskAsset` | ID локального ресурса маски |
| `imageAsset` | ID изображения заполнения |
| `overflow` | clamp: заполнение ограничено диапазоном 0–100% |

Маска ограничивает область заполнения прозрачностью изображения. Для произвольного силуэта нужен ресурс с прозрачным фоном, например PNG или SVG. Непрозрачный прямоугольник даёт прямоугольную маску. Прогресс не меняет форму исходной картинки автоматически.

### Условия, привязка и анимации

Условие сравнивает выбранный показатель с заданным значением. Оно может управлять видимостью или цветом слоя. Постоянное скрытие слоя, скрытие родительской группы и условие могут действовать одновременно; выполнение условия не отменяет другие причины невидимости.

| Поле | Допустимые значения / единицы |
|---|---|
| Условие `metric` | percent / current / remaining |
| Сравнение `op` | gte — не меньше; lte — не больше |
| Действие `action` | show / hide / color |
| Порог `value` | Число −10^15…10^15, в единицах выбранного показателя |
| Группа `layout` | free / horizontal / vertical |
| Группа `gap`, `padding` | 0–8192 px |
| Группа `align` | start / center / end |
| Якорь по горизонтали / вертикали | left / center / right; top / center / bottom |
| Анимация `duration` | 0–60000 мс |
| `easing` | linear / ease / ease-in / ease-out / ease-in-out |
| Событие `event` | none / donation / goal / milestone |
| Эффект `effect` | none / fade / pulse / slide / glow |
| Порог анимации `threshold` | 0–1000000 процентов для события milestone |
| Интенсивность `intensity` | Коэффициент силы эффекта, 0–100 |

Привязка определяет связь с краями/центром холста. Выравнивание, направляющие и сетка помогают размещению, но не создают новый элемент в OBS. Группа объединяет трансформации дочерних слоёв. Отмена/возврат относятся к изменениям документа в редакторе.

Плавность изменения задаётся в миллисекундах; характер движения определяет интерполяцию. Реакция на донат или достижение цели — отдельная событийная анимация. Тестовые события и тестовый прогресс меняют только предпросмотр. Пауза приостанавливает управляемые анимации, в том числе таймеры и анимации программных блоков в предпросмотре.

### Локальные ресурсы

Поддерживаются PNG, JPG/JPEG, WebP, GIF, SVG и шрифты WOFF/WOFF2/TTF/OTF. Один ресурс — до 16 MiB, импорт оформления — до 64 MiB. Ресурс идентифицируется хешем содержимого. Имя в библиотеке не является путём к произвольному файлу компьютера.

Используемые ресурсы защищены от удаления. Корзина позволяет восстановить удалённый ресурс. При переносе используйте ZIP оформления либо полный бэкап: копирование только документа без его файлов может дать отсутствующие картинки или шрифты. Шрифт по имени должен существовать в окружении отображения; загруженный файл шрифта переносится вместе с оформлением.

### Собственный код и ответ ИИ

Режим CSS меняет оформление заданной стандартной структуры и не принимает произвольные HTML/JavaScript. Режим собственного виджета поддерживает HTML/CSS/JavaScript и объявленные параметры. Ответ можно вставить целиком или разнести по полям. Совместимый структурированный ответ использует формат `vdg-ai/1`; обычные слои передаются как `document`.

Для программного слоя допускается до 200000 символов в каждом из HTML/CSS/JS и до 100 объявленных полей. Типы полей: text, number, color, boolean. Необъявленные ключи не принимаются. HTML целиком не превращается автоматически в отдельно редактируемые надписи и фигуры; для этого ответ должен содержать обычные слои документа.

Код работает в изолированном iframe с переданными данными цели. Доступ к странице администратора, ключам сервисов и серверному API не предоставляется. Внешние библиотеки, сетевые запросы и абсолютные пути к файлам не входят в поддерживаемый контракт. Внешняя нейросеть используется пользователем отдельно: программа готовит запрос и проверяет вставленный результат, но не отправляет запрос по встроенному API.

## Донат-сервисы и подключения {#integrations}

Менеджер запускает включённые модули, хранит их конфигурацию и возвращает состояние процесса и соединения. Наличие процесса не подтверждает подписку на события. Перед проверкой изменённые параметры должны быть сохранены. Секретное поле после сохранения показывается как «Сохранено»; пустой ввод при повторном сохранении не удаляет сохранённый секрет.

### DonationAlerts

OAuth 2.0, live-канал Centrifugo и отдельная проверка API. Catch-up после восстановления соединения использует сохранённую контрольную точку; первый запуск не импортирует всю старую историю.

Статус поддержки: **stable**. Публичная конфигурация: `integrations/donationalerts/donationalerts_config.json`.

| Поле | Тип | Стандарт | Назначение |
|---|---|---|---|
| `use_system_proxy` | checkbox | false | Обычно выключено: сервис подключается напрямую, отдельно от прокси браузера. VPN в режиме полного туннеля этой настройкой не обходится. |
| `client_id` | text · обязательно | пусто | Создаётся в разделе API Applications DonationAlerts. |
| `client_secret` | password · обязательно | пусто; секрет | Хранится только локально и не показывается повторно. |
| `redirect_uri` | text | http://127.0.0.1:3333/auth/donationalerts/callback | Должен точно совпадать с Redirect URL в приложении DonationAlerts. |
| `scopes` | text | oauth-user-show oauth-donation-subscribe oauth-donation-index | Для получения профиля, подписки на новые донаты и чтения истории. |


### Donatty

OBS-ссылка виджета используется для получения временного SSE URL. Для поддерживаемой ссылки JWT получается через API; при необходимости доступен браузерный резерв. HTTP-ответ без событий потока не равен подтверждённому приёму донатов.

Статус поддержки: **stable**. Публичная конфигурация: `integrations/donatty/donatty_config.json`.

| Поле | Тип | Стандарт | Назначение |
|---|---|---|---|
| `use_system_proxy` | checkbox | false | Обычно выключено: Donatty подключается напрямую, отдельно от прокси браузера. VPN в режиме полного туннеля этой настройкой не обходится. |
| `widget_url` | password · обязательно | пусто; секрет | Обычная ссылка виджета из кабинета Donatty. Для ссылки widgets.donatty.com/donations/ поток получается напрямую через API, без скрытого браузера. |
| `headless_browser` | checkbox | true | Выключите только для отладки Playwright. |
| `prefer_auto_sse` | checkbox | true | Автоматически получать SSE URL |
| `use_old_sse_if_auto_failed` | checkbox | true | Использовать сохранённый SSE как резерв |
| `sse_capture_timeout_seconds` | number | 35 | Таймаут получения SSE, сек. |
| `reconnect_delay_seconds` | number | 5 | Начальная задержка переподключения, сек. |
| `max_reconnect_delay_seconds` | number | 60 | Максимальная задержка переподключения, сек. |


### StreamElements

События completed tips принимаются по официальному real-time каналу. Фильтры статуса и модерации относятся к приёму события. Интеграция отмечена Beta.

Статус поддержки: **beta**. Публичная конфигурация: `integrations/streamelements/streamelements_config.json`.

| Поле | Тип | Стандарт | Назначение |
|---|---|---|---|
| `channel_id` | text · обязательно | пусто | ID канала/room, для которого нужно получать tips. Берётся из StreamElements Dashboard. |

### Tribute

OBS-ссылка из мини-приложения преобразуется в SSE-подключение. Cloudflare не нужен. При проверке включается двухминутное окно; учёт событий в этом окне задаётся переключателем. Надёжного отдельного признака тестового доната в потоке нет: имя Anonymous и сумма 999 сами по себе не доказывают тест. Гарантия восстановления событий за время полного отключения не заявляется.

|---|---|---|---|

| `count_during_test` | checkbox | false | Действует только в двухминутном режиме проверки. Вне проверки учитываются все донаты, включая Anonymous на 999 ₽. Tribute не помечает тесты: тест, отправленный вне режима проверки, тоже будет учтён. |
| `use_system_proxy` | checkbox | true | Оставьте включённым для работы через системный прокси/VPN. После изменения сохраните настройки и перезапустите интеграцию. |


### Общие ограничения сети

Прямой режим соединения может обходить системный HTTP-прокси, но не отменяет VPN с перехватом всего трафика. Доступность сайта в браузере и API в процессе может различаться. Тайм-аут сообщает о проблеме доставки ответа; он сам по себе не доказывает блокировку сервиса или неверность токена.

## Streamer.bot {#streamerbot}

Отдельная вкладка «Интеграции → Streamer.bot» управляет выходными оповещениями. Это не источник донатов и не провайдер озвучки. Bridge запускается менеджером Core; повторный стандартный запуск не должен создавать второй Bridge.

| Параметр | Назначение / стандарт |
|---|---|
| `enabled` | Включение Bridge, в чистой сборке false |
| `streamerbot_http_url` | HTTP endpoint действия: `http://127.0.0.1:7474/DoAction` |
| `action_name` | Точное имя Action, если ID не указан |
| `action_id` | ID Action, имеет приоритет над именем |
| `poll_interval_seconds` | Интервал чтения новых донатов, 0,5 с в примере конфигурации |
| `send_existing_on_first_start` | Обычно false: первый запуск не должен проигрывать старую историю |
| `send_sources` | Пустой список разрешает автоматические источники; ручные записи управляются флагом оповещения |
| `extra_args` | Дополнительные аргументы действия; сохраняются при редактировании основных настроек в интерфейсе |

Загрузка действий использует HTTP GetActions. Проверка подключения проверяет доступность API и выбранного Action, ничего не проигрывая. «Тестовое оповещение» вызывает Action один раз с TestUser и суммой 133 RUB; оно не создаёт донат, запись TTS или сумму сбора.

| Аргумент Action | Содержание |
|---|---|
| `user` | Имя донатера |
| `amount` | Сумма |
| `currency` | Валюта в выбранном режиме представления, например ₽ |
| `message` | Сообщение |
| `source` | Источник доната |
| `donationId` | Идентификатор записи |

Дополнительные Donation Event Rules находятся в `integrations/streamerbot/donation_event_rules.json`. Они имеют собственную защиту от повторной отправки, отдельную от основного Action. Пошаговое создание сцены OBS и готовый C# находятся в Гайдбуке, а не требуются для любого подключения Streamer.bot.

## Озвучка и голосовые правила {#tts}

TTS Hub принимает событие, обрабатывает текст, выбирает профиль по правилам и направляет задание провайдеру. Приоритет правил задаёт порядок выбора профиля, а не порядок очереди воспроизведения. Speaker.bot выводит речь самостоятельно; провайдеры с аудиофайлом используют браузерный проигрыватель `/tts.html` в OBS.

### Общая последовательность

```text
Событие
  ↓
Проверка TTS-флага и суммы
  ↓
Очистка текста
  ↓
Выбор профиля
  ↓
Выбор основного провайдера
  ↓
Синтез / отправка Speaker.bot
  ↓
При подтверждённой ошибке — fallback
  ↓
История и лог
```

### Общие настройки

- основной провайдер;
- резервный провайдер;
- профиль по умолчанию;
- минимальная сумма автоматического доната;
- максимальная длина;
- удаление ссылок и HTML;
- пропуск пустого текста;
- автоматическая озвучка донатов сервисов.

Важно: провайдер, жёстко заданный в профиле, имеет приоритет. Значение **«Автоматически»** заставляет профиль использовать основной провайдер.

### Провайдер Speaker.bot

Speaker.bot удобен как общий голосовой центр для донатов, команд, наград и внешних событий.

#### Настройка Speaker.bot

1. Открой `Settings -> Speech Engines`.
2. Добавь и настрой движок.
3. Открой `Settings -> Voice Aliases`.
4. Создай alias, например:

```text
Donations
moderator
Rewards
Custom
```

5. Проверь `Test Speak`.
6. Открой `Settings -> Websocket Server`.
7. Включи Auto Start.

Пример текущей конфигурации:

```text
Address: 127.0.0.1
Port: 7580
Endpoint: /
```

В VicDonationGoal:

```text
ws://127.0.0.1:7580/
```

Название Voice Alias в профиле должно совпадать символ в символ.

#### Очередь Speaker.bot

VicDonationGoal умеет отправлять команды:

```text
Pause
Resume
Stop
Clear
```

Fallback запускается только при подтверждённой ошибке отправки. Медленная речь Speaker.bot сама по себе не запускает второй голос.

#### Типичные ошибки

```text
speakerbot: выключен
```

Проверь флаг провайдера, профиль и WebSocket.

```text
Voice Alias не указан
```

Создай alias и впиши его в профиль.

### Правила маршрутизации

Правила выбирают профиль. Они **не задают порядок проигрывания очереди**.

Главное правило:

```text
меньше число приоритета = правило проверяется раньше
```

Срабатывает первое подходящее правило.

#### Типы событий

Стандартные значения:

```text
donation
channel_reward
custom
moderator_command
manual_test
custom
```

Это внутренние значения TTS Hub. Они не появляются автоматически из Twitch или YouTube — их передаёт создатель события.

#### Источники

Стандартные значения:

```text
donationalerts
donatty
manual
streamerbot
twitch
youtube
external
custom
```

Пример:

```text
eventType = channel_reward
source = streamerbot
```

означает, что Streamer.bot получил награду и отправил её в TTS Hub.

#### User ID

Постоянный ID пользователя Twitch, YouTube или другой платформы. Он надёжнее ника, но доступен только если внешняя система его передала.

#### Ники

Сравнение выполняется без учёта регистра. У донатов DA/Donatty ник обычно доступен, а platform userId — не всегда.

#### Роли

Примеры:

```text
moderator
vip
subscriber
broadcaster
```

Роль сработает только если Streamer.bot или другая интеграция передала поле `roles`.

#### Reward ID

ID конкретной награды Twitch. Его можно получить из события Streamer.bot или из настроек награды.

#### Сумма

Правила могут ограничить минимальную и максимальную сумму. Сначала используется `amountForGoal`, затем обычный `amount`.

#### Как объединяются условия

Разные заполненные поля работают через **И**. Значения внутри одного поля, перечисленные через запятую, работают через **ИЛИ**.

Пример:

```text
Тип: donation
Источник: donatty, donationalerts
Ник: Nick
Минимальная сумма: 1000
```

означает: донат из Donatty или DA, от Nick, не меньше 1000.

#### Тестер маршрутизации

В разделе правил можно ввести тестовое событие и увидеть:

- совпавшее правило;
- выбранный профиль;
- фактический провайдер;
- голос;
- fallback.

Озвучка при этом не запускается.

### Очередь, история и логи

#### Очередь

Показывает ожидающие, обрабатываемые и готовые задачи. Длинный текст раскрывается вниз.

#### История

Фильтры:

- поиск по нику, тексту и ID;
- статус;
- провайдер.

Развёрнутая запись показывает:

- оригинальный текст;
- текст после очистки;
- удалённые ссылки и фрагменты;
- профиль;
- совпавшее правило;
- провайдер и голос;
- fallback;
- ошибку;
- идентификаторы события.

Статус `Пропущено` не является аварией. Например, сообщение могло состоять только из ссылки и стать пустым после очистки.

#### Логи

Логи хранят технические события TTS. Секретные ключи нельзя добавлять в текст ошибок вручную.

### Внешний TTS API

Главный endpoint:

```text
POST http://127.0.0.1:3333/api/tts/enqueue
```

Минимальный пример:

```json
{
  "eventType": "channel_reward",
  "source": "streamerbot",
  "username": "Viewer",
  "text": "Сообщение зрителя"
}
```

Расширенный пример:

```json
{
  "eventType": "channel_reward",
  "source": "streamerbot",
  "eventId": "reward-event-id",
  "username": "Viewer",
  "userId": "123456789",
  "roles": ["moderator"],
  "rewardId": "twitch-reward-id",
  "text": "Сообщение зрителя",
  "profileId": "moderator",
  "priority": 50
}
```

Если указан существующий `profileId`, правила пропускаются и профиль выбирается напрямую.

Проверка правил без озвучки:

```text
POST /api/tts/rules/test
```

## Главная, темы и настройки интерфейса {#interface}

Настройки интерфейса хранятся в `core/ui_settings.json` отдельно от документа OBS. Главная использует сетку из 12 колонок. Доступны блоки подключений, последних донатов, цели, ручного ввода, озвучки, TopDonation, сводки, курсов, очереди, теста TTS, истории речи и сервисов. Блоки можно добавлять, удалять, перемещать и изменять их размер с учётом минимальных размеров. Освободившиеся верхние места занимаются автоматически.

| Поле темы | Значения |
|---|---|
| `mode` | dark / light |
| `family` | monocrome / vicwander |
| `base` | Палитра основы; варианты neutral, stone, zinc, slate, gray и цветные палитры |
| `accent` | Независимая палитра акцента |
| `baseSaturation` | 0–100, стандарт 35; насыщенность оттенка основы |

Всего 26 семейств палитр. Базовый Monocrome использует нейтральные поверхности и белые кнопки в тёмном режиме. Насыщенность меняет цветность основы, сохраняя заданную светлоту поверхностей. Цвета состояния подключения и обозначения сервисов имеют собственный смысл и не становятся цветом темы.

## Хранение, резервные копии и перенос {#data}

| Данные | Расположение |
|---|---|
| Цель и история | `core/data/state.json`, `core/data/donations.json` |
| Профили и корректировки TopDonation | `core/data/donor_profiles.json`, `core/data/donor_adjustments.json` |
| Интерфейс | `core/ui_settings.json` |
| Оформления | `core/widget_settings.json` |
| Ресурсы оформлений | `core/widget_assets/` |
| Подключения | Конфигурации и токены в `integrations/` |
| TTS | Конфигурация, профили, правила, очередь и история в `integrations/tts/` |
| Служебные отметки отправки | `*_sent.json` и поддерживаемые файлы состояния модулей |
| Резервные копии | `backups/` |
| Диагностические отчёты | `diagnostics/` |

Полный бэкап содержит поддерживаемые пользовательские файлы, в том числе секреты подключений, оформления и ресурсы. Схема бэкапа — 1; неизвестная более новая схема отклоняется. Ограничения импорта: до 64 MiB загружаемого файла, до 128 MiB распакованных данных, до 500 файлов. Проверяются пути, формат и содержимое, а не только расширение ZIP.

Импорт истории защищается от дублей. Полный перенос конфигурации требует остановленных внешних модулей; для переноса из папки предназначен `16_UPDATE_FROM_OLD_VERSION.bat`. Перед изменением создаётся резервная копия. Бэкап не является способом переносить старый исполняемый код поверх новой версии.

Не публикуйте настроенную папку, OAuth-токены, ссылки виджетов и полные бэкапы. Локальная админка не предназначена для открытого доступа из интернета. Пользовательский HTML виджета изолируется от страницы управления, но доверие к внешнему файлу или коду всё равно требует проверки результата до применения.

## Состояния, ошибки и диагностика {#diagnostics}

| Состояние | Значение |
|---|---|
| Выключено | Модуль отключён настройкой |
| Не настроено | Не заполнены обязательные параметры |
| Остановлено | Модуль включён, но процесс не запущен |
| Подключение | Запуск или ожидание подтверждения соединения |
| Подключено | Есть подтверждение, предусмотренное данным обработчиком |
| Требует внимания | Переподключение, устаревший статус, ограничение частоты или другой неполный рабочий режим |
| Ошибка | Конфигурационная, авторизационная или продолжительная сетевая ошибка |

`running` относится к процессу, `connected` — к подтверждённому каналу, `stale` — к возрасту последнего обновления состояния. В техсостоянии сохраняются последняя ошибка, событие и время обновления. Для DonationAlerts OAuth/API, live-подписка и догон истории — отдельные признаки.

| Симптом | Что проверить |
|---|---|
| API отвечает, донатов нет | Подписку/канал событий, параметры фильтра, тип теста сервиса и последнее событие |
| 401/403, Incorrect token | Актуальность и тип ключа, OAuth, регион DonatePay |
| ReadTimeout | Сеть, прокси/VPN и доступность API; это не признак успешной доставки |
| Bridge запущен, оповещения нет | HTTP Server Streamer.bot, выбранный Action, его очередь и источники OBS |
| Speaker.bot: ConnectionRefused | Запуск Speaker.bot и его WebSocket Server, адрес и порт 7580 |
| Edge создал файл, но звука нет | Проигрыватель `/tts.html` в OBS и аудиомаршрутизацию |
| Старые записи проигрались повторно | Сброс служебных sent-файлов, ручной повтор или запуск двух копий |
| Конфликт редактора | Документ изменён в другом окне; обновить состояние перед записью |

«Диагностический отчёт» и `14_CREATE_DIAGNOSTIC_REPORT.bat` создают ZIP с маскировкой секретов без текстов донатов. Это формат для поддержки. Полный бэкап для поддержки не требуется. `09_STABILITY_CHECK.bat` проверяет структуру установки; `15_BETA_READINESS_CHECK.bat` — расширенные офлайн-проверки (историческое имя файла не означает Beta-статус всей версии).

## Архитектура и API {#api}

Core обслуживает локальный HTTP API и хранение. Integration Manager читает manifests, запускает включённые обработчики и возвращает их состояние. Интеграции приводят платежи к единому событию; Streamer.bot Bridge и TTS Hub обрабатывают уже записанные данные. Исходные валюты и источник сохраняются.

```json
{
  "source": "manual",
  "externalId": "example-1",
  "username": "Viewer",
  "amount": 100,
  "currency": "RUB",
  "message": "Спасибо за стрим",
  "includeInGoal": true,
  "includeInTop": true,
  "notifyStreamerBot": false,
  "triggerDonationEvents": false,
  "speakTTS": false
}
```

API локальной админки — внутренний интерфейс приложения, а не размещённый облачный сервис. JSON-запросы используют Content-Type application/json. Ошибки возвращают HTTP-код и диагностическое сообщение. Для защищённых операций проверяются локальный контекст запроса и поддерживаемая схема; обходить эти проверки внешней публикацией сервера не следует.

### Контракт редактора

Документ использует `schemaVersion: 1`. Изменяющие запросы редактора передают текущую `revision`; конфликт возвращает 409. Неверный документ или отсутствующий ресурс отклоняются. `draft`, `apply`, `save`, `load`, `revert`, `delete` — отдельные действия: сохранение варианта и применение в OBS не равнозначны.

| API виджета | Назначение |
|---|---|
| GET `/api/widget/editor` | Настройки редактора, черновик, ресурсы |
| GET `/api/widget/active` | Активный документ |
| POST `/api/widget/draft` | Сохранить черновик с revision |
| POST `/api/widget/apply` | Применить документ |
| POST `/api/widget/save` | Сохранить вариант |
| POST `/api/widget/load` | Загрузить вариант в черновик |
| POST `/api/widget/revert` | Вернуть предыдущее применённое оформление |
| POST `/api/widget/delete` | Удалить сохранённый вариант |
| POST `/api/widget/assets?filename=…` | Загрузить ресурс |
| POST `/api/widget/assets/rename` | Переименовать ресурс в библиотеке |
| POST `/api/widget/assets/trash` | Переместить неиспользуемый ресурс в корзину |
| POST `/api/widget/assets/restore` | Восстановить ресурс |
| GET `/api/widget/export?kind=draft` | Экспорт ZIP оформления |
| POST `/api/widget/import?revision=…` | Проверить и импортировать ZIP |

Пошаговые примеры собственных элементов и формат ответа ИИ находятся в Гайдбуке. Формат и ограничения схемы проверяются на сервере: успешный предпросмотр не отменяет проверку при сохранении и применении.
